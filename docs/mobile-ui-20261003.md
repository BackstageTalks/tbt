# Mobile presentation refresh

The mobile header (up to 900px) now contains a hamburger, the existing BlinQ logo, a purple PP shortcut for joined project groups, the original Info bell, and the original account avatar/menu. A single joined group opens directly; multiple groups open a selector; users without groups do not receive a PP shortcut.

The adapter invokes original controls so route access checks, locked tabs, membership upgrades, Info messages and account actions remain owned by app.js. It never creates another feed or auth client. The public project directory entry is hidden in the mobile profile menu; project administration remains available through the existing Admin screen. This is a navigation change, not a new backend authorization policy.

Prediction cards use stacked players and larger text. Results place the prediction on its own row to accommodate long names. Existing banner configuration and Telegram rendering remain unchanged. Desktop and admin-route styles are excluded. The footer/bottom navigation are removed on mobile and language links are exposed in the hamburger.

Files: web/blinq-mobile.css, web/blinq-mobile.js, two includes in web/index.html. Remove the includes to roll back after reloading.

Validation:
- browser_mobile_header.py: 320/390/900/1440px, 0/1/multiple groups, original avatar menu, typography, no header collisions, no script errors.
- browser_mobile_results_layout.py: 320/360/390/430/768/900/1024/1440px, long names and tournament names, filters and card bounds, Escape and avatar behavior.
- browser_info_sg_detail.py: existing ROOKIE Info delivery, bell/drawer and Sets/Games Detail behavior.

Tests use offline deterministic fixtures and real app renderers. They make no production writes. Authenticated staging and physical iOS/Android verification remain before production release. Set BLINQ_BROWSER to a Chromium executable and optionally BLINQ_SCREENSHOTS to a directory for review images.
