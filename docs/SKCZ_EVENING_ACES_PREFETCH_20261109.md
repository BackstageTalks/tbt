# SK/CZ evening tennis-aces quote research (initial Fortuna SK pilot)

## Purpose
Capture publicly visible **pre-match** ESÁ player Over/Under lines and full-match VIAC ES outcomes **the evening before** BlinQ's 06:00 Bratislava betting day, preserving original observed pricing and timestamps. No model training, CDB import, morning quote replacement, Telegram publication or historical mutation.

This is a **research pilot**, not an operational claim of SK/CZ ace-price coverage. The public Fortuna pages verified on 2026-11-09 showed ordinary tennis prices and structured outcome IDs, **but no ace market in the tested matches**. A valid zero-ace result must remain a zero-ace result.

## Timing and source
- External cron only: send `repository_dispatch` event `blinq-fortuna-evening-odds-tick` to `.github/workflows/skcz-evening-odds.yml` at **22:00 Europe/Bratislava** for the next betting day (e.g. collection 9 Nov at 22:00 for the 10 Nov betting day). This is normally **7h15m before** the existing 05:15 morning-refresh workflow and **8h20m before** the Telegram 06:20 queue; across daylight-saving changes, elapsed durations may differ. Never activate GitHub's native schedule. Configure the **existing external scheduler** using the `Europe/Bratislava` timezone (not a fixed UTC offset).
- Run no more than 20 public event-detail requests by default (absolute parser cap: 60). Exponential retries, proxy rotation, auth bypass or session reuse are not part of this collector.
- First source: https://www.ifortuna.sk/stavkovanie/tenis?tab=matches and its published detail links.
- Parse each named match's stable provider event ID, player labels, scheduled start, individual market ID, outcome ID, actual decimal price and market line. Keep only matches between 06:00 local on the target betting day and 06:00 the next day.
- Accept a player-aces O/U only when two OPEN selections in **one** market ID share exactly the same line, opposite sides, and the market names exactly one player. Never infer a bookmaker line from model projection.
- Accept full-match VIAC ES candidate only when precisely two OPEN named players are listed in one market ID; preserve settlement uncertainty pending a bookmaker rule/readback check. Set-specific variants must not be treated as full-match.
- Ordinary match-winner, games, sets, synthetic statistical odds or O/U-to-superiority conversions are not accepted as ESÁ/VIAC ES.

## Storage, isolation, readback
- The workflow generates a local JSON report; it validates zero canonical writes, zero paid-provider calls and zero published-pick changes.
- With existing TBT_DATA_GH_TOKEN permissions, create a **new, immutable research file** at \`BackstageTalks/tbt-data:research/skcz-evening-odds/<betting_day>/fortuna-<github_run_id>.json\`.
- No update, delete, overwrite or writer lock is needed because this is a separate create-only research path, *not* the canonical CDB. The workflow then downloads the exact file from GitHub and checks its SHA-256 against the generated bytes.
- Upload a short-lived Actions artifact if persistent archive upload or source fetching fails. Missing source access is an error; a successful market scan with no exact ace quote is marked \`no_exact_aces_market_available\`, **not** confirmed bettable availability.
- A guarded morning reader is implemented in `scripts/skcz_evening_quotes.py` and called by `scripts/pipeline.py` only for morning refresh. It requires unique match/player/date and exact ESÁ model line, and rejects observations after match start. Historical picks or previously priced provider quotes are never modified. It falls back to existing BlinQ odds when no exact eligible quote exists. **Production read-back and live market coverage remain unverified**; the archived evening snapshot is not automatically evidence of current bettable availability at the morning decision timestamp.
- Do not present absent SK/CZ ace markets as synthetic bookmaker prices.

## Approved morning behavior — exact quote or existing fallback

Only Fortuna SK is in scope for this pilot; Tipsport is excluded.

- At 22:00 Bratislava, a read-only collector stores optional exact bookmaker ESÁ/VIAC ES quotes in a private, separate, create-only research path.
- During the existing morning model selection, unchanged model-selected ESÁ and VIAC ES bets receive an exact pre-match Fortuna quote **only when** player identity, event start, market contract and ESÁ O/U line match unambiguously. Existing provider-backed prices are never overwritten.
- Without a matching Fortuna quote, use the **pre-existing** local price behavior: ESÁ 1.60–1.80 and VIAC ES 1.50–1.70; preserve their internal non-bookmaker provenance. A missing/stale research snapshot never blocks or deletes a valid model pick.
- Do not change the approved model, selected event count, the CDB, historical Results, already published picks or Admin categories. The fallback is not a claim that Fortuna offered that selection.
- UI contract requested by the owner: **no new badges, price-source text, bookmaker names, icons, tags or extra rows**. Existing price values fit the same card layout. For ESÁ / VIAC ES, remove the previously rendered tiny labels under price numbers (e.g. "Štat. kurz BlinQ", "Kurz API Pro") so both sources display only a price number, without a second-line source tag.
- Private provenance and audit remain inside the canonical publication data and research report, not as additional website labels.

**Implementation status:** Morning attachment, internal price verification and the tiny ESÁ/VIAC ES source-label removal are prepared in PR #1514, but not merged, deployed or independently runtime-tested. This is not evidence of actually bettable ESÁ/VIAC ES quotes from Fortuna.
